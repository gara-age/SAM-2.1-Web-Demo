# SAM 2.1 Vision Console

## 같은 학교망에서 접속

LAN 모드는 `.cache/lan-config.json`의 `enabled`, `port`, `origins` 설정을 `start.ps1`이 읽어 실행합니다. LAN 모드가 없거나 꺼져 있으면 기존처럼 127.0.0.1에서만 실행합니다. `origins`의 주소를 HTTP 제어 요청과 WebSocket 양쪽에서 허용합니다. 로컬 설정 파일은 Git에서 제외됩니다.

Windows 방화벽 규칙은 관리자 PowerShell에서 프로젝트의 `setup-lan-firewall.ps1`을 실행해 추가합니다. 예:

```powershell
.\setup-lan-firewall.ps1 -LocalAddress 172.16.52.67 -RemoteSubnet 172.16.52.0/24 -Port 8000
```

이 규칙은 해당 로컬 IP와 이더넷 인터페이스의 TCP 8000을 지정된 원격 대역에 허용합니다. 방화벽 전체를 끄지 않습니다. 현재 Windows 계정이 일반 사용자이면 관리자 계정 승인이 필요합니다. 적용 결과는 `.cache/lan-firewall-result.json`에서 확인합니다.

다른 PC에서 서버의 LAN 주소로 접속합니다. 접속한 사람들은 서버의 카메라·선택·추적 상태를 공유합니다. IP나 학교망 대역이 바뀌면 로컬 LAN 설정과 방화벽 규칙을 함께 갱신해야 합니다.

## 실시간 클릭 선택과 이미지 평면 보기

- 모델을 먼저 불러오고 USB 카메라를 연속 재생 모드로 시작합니다. 선택 객체가 없으면 **실시간 클릭 선택**이 자동으로 켜집니다. 움직이는 원본에서 대상 안쪽을 왼쪽 클릭하면 프레임 고정·별도 확정 없이 분할 후 자동 추적합니다.
- 새 대상을 선택하려면 **실시간 클릭 선택**을 다시 켜고 클릭합니다. 이 방식은 기존 선택 목록을 새 객체 한 개로 교체합니다. 다중 객체 추가·제외 지점 보정은 기존 **객체 추가 · 프레임 고정**을 사용합니다. 업로드 파일과 순차 분석은 기존 선택 흐름을 사용합니다.
- 서버는 화면에 표시된 클릭 프레임과 좌표를 함께 받습니다. 분할 중에도 카메라 수신과 원본 표시는 계속되고, 받은 프레임을 순서대로 따라잡은 뒤 결과를 표시합니다. 입력 변경·취소·버퍼 만료·대상 소실 시 오래된 마스크를 현재 영상에 억지로 적용하지 않습니다. SAM 3.1처럼 처리가 느리면 다시 클릭해야 할 수 있습니다.
- 오른쪽 **이미지 평면 · 바로 보기**에서는 선택한 객체의 같은 프레임 이미지와 마스크로 배경을 제거한 평면을 즉시 보여 줍니다. 이미지 비율을 유지하며 드래그 회전·휠 확대·자동 회전·시점 초기화를 지원합니다. 선택·추적 결과에 맞춰 이미지가 갱신됩니다.
- 이 모드는 두께와 깊이가 없는 2D 이미지 평면입니다. 뒷면이나 실제 3D 형상을 생성하지 않습니다. 기존 입체 복원은 옆의 **다중 시점 3D 스캔**으로 전환해서 사용합니다. 이미지 평면 미리보기는 긴 변 최대 1024px로 표시하며 원본 좌표 측정값은 바꾸지 않습니다.

## 순차 분석 완료 후 결과 영상 재생

SAM 2.1과 SAM 3.1 모두 다음 흐름을 지원합니다.

1. 동영상 파일을 불러오고 대상을 선택합니다.
2. **재생·추적 방식 → SAM 순차 분석 · 처리 속도로 재생**을 선택하고 **선택 확정 · 추적**을 누릅니다.
3. 카메라 화면 아래 **순차 분석 결과 영상**에서 프레임 진행률을 확인합니다.
4. 분석과 인코딩이 완료되면 마스크·윤곽선·객체 번호가 합성된 결과를 재생합니다. 탐색, 0.5×/1×/1.5×/2× 재생과 MP4 다운로드를 지원합니다.

결과는 `D:\SAM2TrackingWeb\data\recordings\<id>\tracking.mp4`와 `result.json`에 보관합니다. 브라우저 호환 H.264/yuv420p, 원본 FPS를 사용하며 원본 음성은 포함하지 않습니다. FFmpeg의 `libx264` 인코더가 필요합니다. 현재 PC에서는 설치된 FFmpeg를 사용하며 모든 입력·인코딩 결과·로그는 D드라이브에 저장합니다.

일시정지 후 다시 시작하면 같은 영상에 이어서 저장합니다. 선택 보정, 객체 삭제, 모델·입력·추적 방식 변경 또는 추적 종료 시에는 해당 구간을 **중단된 분석 구간**으로 구분합니다. 원본 중간 프레임부터 시작하면 그 이후 구간만 저장합니다. 전체 프레임 누락 없이 끝난 결과만 **분석 완료**로 표시합니다. 서버 재시작 후에도 완료 영상을 목록에서 다시 재생할 수 있습니다. 기존에 분석이 끝난 영상은 프레임별 결과를 저장하지 않았으므로 새 기능으로 다시 순차 분석해야 합니다.

이 기능은 업로드한 동영상의 SAM 순차 분석용입니다. 연속 재생의 광학흐름 보간 결과나 USB 입력을 자동 녹화하지 않습니다.

USB 웹캠 영상에서 객체를 클릭해 분할하고 추적하는 로컬 웹 애플리케이션입니다.
설치 위치: `D:\SAM2TrackingWeb`.

## 이미지·동영상 파일 및 실시간 입력

- 왼쪽 **이미지·동영상 불러오기**에서 내 파일을 선택합니다. JPG, JPEG, PNG, WebP, BMP 및 MP4, MOV, AVI, MKV, M4V, WebM 확장자를 지원하며 동영상은 설치된 OpenCV에서 코덱을 읽을 수 있어야 합니다.
- 파일당 최대 250MB, 프레임당 최대 1,600만 픽셀 및 한 변 8192px입니다. 좌표·마스크·크기는 파일 원본 해상도를 사용합니다. 카메라용 해상도 설정은 파일에 적용하지 않습니다.
- 이미지는 클릭 또는 SAM 3.1 텍스트로 분할·측정하고 **선택 확정**을 누릅니다. 정지 이미지 한 장으로 3D 스캔을 만들 수는 없습니다.
- 동영상은 첫 화면에서 객체를 선택한 뒤 **선택 확정 · 추적**을 누릅니다. 기본 **연속 재생 · 광학흐름 + SAM 보정**에서는 영상 디코딩과 광학흐름 추적이 AI 추론과 별개로 진행됩니다. 선택한 SAM 2.1 또는 3.1 모델이 백그라운드에서 실제 마스크를 보정합니다. 음성 재생은 포함하지 않습니다.
- **추적 일시정지** 후 다시 시작하면 이어서 분석합니다. 영상 끝에서는 자동 정지합니다. **처음으로 · 선택 초기화**로 첫 화면으로 돌아갑니다. 되감기와 새 파일 열기는 선택 객체를 초기화합니다.
- JSON 내보내기의 `frame.source_index`는 0부터 시작하는 원본 프레임 번호, `frame.source_time`은 원본 영상 시작 기준 초입니다. 영상 시간은 원본 FPS를 기준으로 계산하며, FPS를 읽지 못하면 30으로 가정합니다.
- 업로드 사본은 `D:\SAM2TrackingWeb\data\uploads`에 저장됩니다. 파일 입력은 기존 USB 입력을 대체하며 원본 파일 자체는 수정하지 않습니다. 업로드 파일은 Git에서 제외됩니다.
- **실시간 USB 카메라**는 기존 카메라 시작 기능을 사용합니다. 파일 입력 중이면 **파일 닫기** 후 카메라를 시작하세요. 두 모델 모두 연속 추적 모드를 사용할 수 있습니다. SAM 3.1 자체의 추론 속도가 빨라지는 것은 아니며, SAM 처리 사이에는 광학흐름 추정 마스크를 표시합니다. 카메라 수신, 보간 추적, AI 처리 FPS는 별개입니다.

## 실행

1. `D:\SAM2TrackingWeb\start.cmd`를 실행합니다.
2. 브라우저에서 http://127.0.0.1:8000 에 접속합니다.
3. `카메라 시작`을 누릅니다. 카메라가 여러 개면 먼저 `탐색`으로 장치를 선택합니다.
4. `모델 불러오기`를 누릅니다. 생략해도 첫 분할 시 자동으로 로딩됩니다.
5. `객체 추가 · 프레임 고정`을 누르고 영상의 객체 안쪽을 좌클릭합니다.
6. 마스크를 확인하고, 필요하면 좌클릭으로 포함 지점, 우클릭으로 제외 지점을 추가합니다.
7. **`선택 확정 · 추적`을 눌러 영상의 움직임을 추적합니다.** 선택 중 영상이 고정되는 것은 정상 동작입니다.
8. 다른 객체를 추가하려면 `객체 추가`를 다시 누릅니다. 기존 객체의 마스크가 있는 분석 프레임에서 새 객체를 선택합니다.
9. 보정하려면 객체를 선택하고 `보정`을 누릅니다. 지점을 수정한 뒤 다시 확정합니다.

서버 종료는 실행 창에서 Ctrl+C입니다. USB 카메라는 서버 시작만으로 켜지지 않고 웹 화면의 시작 버튼으로 켜집니다.
실행 중인 서버가 있으면 새로 시작하지 말고 기존 주소로 접속하세요. 이 앱은 한 서버에 하나의 공유 작업 상태를 사용하므로 여러 탭의 조작이 같은 작업에 반영됩니다.

## 화면과 측정값

- **분석 프레임:** 마스크와 해당 원본 프레임을 함께 표시합니다. 갱신 속도는 추론 속도에 따릅니다.
- **실시간 원본:** 최신 카메라 영상입니다. 다른 시점의 마스크를 잘못 겹치지 않도록 분석 마스크를 표시하지 않습니다.
- **선택 지점:** 원본 영상의 정수 `(x, y)`, 포함/제외, 선택 당시 프레임 ID입니다. 추적 중 이 지점을 객체의 현재 좌표로 사용하지 않습니다.
- **크기:** 바운딩 박스의 너비·높이(px), 마스크의 실제 픽셀 수(px²), 전체 영상 대비 면적 비율입니다.
- **경계:** `[x_min, y_min, x_max, y_max]` 및 네 꼭짓점, 실제 마스크의 전체 윤곽선 픽셀 좌표입니다. 윤곽선의 `parent` 인덱스로 분리 영역과 구멍의 계층을 확인할 수 있습니다.
- **중심:** 마스크 픽셀 좌표들의 평균인 무게중심입니다. 박스의 중심과 다를 수 있고 오목한 물체에서는 마스크 밖에 위치할 수도 있습니다.
- 원점은 **원본 영상의 왼쪽 위**입니다. x는 오른쪽, y는 아래쪽으로 증가합니다. 화면의 확대/축소를 클릭 좌표 변환에 반영합니다.
- 경계 최댓값은 포함되는 픽셀 인덱스입니다. 너비는 `x_max - x_min + 1`, 높이는 `y_max - y_min + 1`입니다.
- 픽셀 좌표는 2D 영상상의 값입니다. cm·mm 또는 3D 좌표를 뜻하지 않습니다.
- `Pending`: 아직 분할되지 않음. `Active`: 현재 결과에 마스크가 있음. `Lost`: 이전에 선택됐지만 현재 마스크가 비어 있음. 추적 실행/일시정지 여부는 영상 하단에 별도로 표시됩니다.
- 빈 마스크에서는 유효한 크기·중심·경계 좌표를 표시하지 않습니다. 신뢰도 수치를 임의로 만들지 않습니다.
- 마스크·윤곽선·박스·중심점·경로·지점은 각각 표시를 켜고 끌 수 있습니다. 객체별 숨기기와 삭제도 지원합니다.
- 지점 상세 목록의 삭제, 마지막 지점 취소, 현재 지점 초기화를 사용할 수 있습니다. 제외 지점만 남으면 포함 지점을 먼저 추가해야 합니다.
- 경로는 최근 120개의 중심 측정값입니다. 객체를 선택한 후 `이동 경로 초기화`로 지울 수 있습니다.

## 내보내기

상단의 JSON 또는 CSV 버튼을 사용합니다. 마지막으로 게시된 분석 프레임과 그 측정값을 내보냅니다.
JSON에는 선택 지점, 윤곽선 원본 좌표, 경로, 영상 크기, 프레임 ID 및 Unix 시각이 포함됩니다.
CSV에는 객체별 크기·중심·박스·선택 지점 요약이 포함되며, Excel에서 한글이 열리도록 UTF-8 BOM을 사용합니다.
영상·마스크 이미지 자체는 내보내기에 포함하지 않습니다. 필요하면 별도 녹화/이미지 저장 기능으로 확장할 수 있습니다.

## 설치 및 저장 공간

이미 이 PC에는 설치와 빌드가 완료되어 있습니다. 재설치할 때 프로젝트 폴더에서 다음을 실행합니다.

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\setup.ps1
```

Python 3.10 이상, Node.js, Git, NVIDIA CUDA 호환 드라이버가 필요합니다.
현재 환경은 Python 3.10.11 / Node 24.17 / RTX 2080 SUPER 8GB이며 PyTorch 2.5.1+cu121을 사용합니다.
설치 스크립트는 시스템 Python 환경 대신 프로젝트의 `.venv`를 사용합니다.

| 경로 | 내용 |
|---|---|
| `.venv/` | Python 및 CUDA용 PyTorch 패키지 |
| `.cache/pip/`, `.cache/npm/` | 다운로드 캐시 |
| `.cache/tmp/`, `.cache/frames/` | 설치 및 프레임 처리 임시 파일 |
| `models/sam2.1_hiera_tiny.pt` | 공식 모델 체크포인트, 약 149MiB |
| `vendor/sam2/` | Meta 공식 소스, 고정 커밋 |
| `backend/` | FastAPI, 카메라, 모델 어댑터 및 좌표 계산 |
| `frontend/` | React + TypeScript + Vite, `dist/` 빌드 산출물 |
| `tests/`, `scripts/` | 단위/API 테스트와 실제 모델 통합 검증 |
| `logs/` | 검증 결과 JSON, 환경 기록 |

위의 대용량 파일과 앱의 다운로드·임시 캐시는 D드라이브에 둡니다.
Windows와 브라우저 자체의 시스템 캐시 위치는 변경하지 않습니다.
`setup.ps1`은 현재 검증한 SAM 커밋을 사용합니다. 프로젝트를 다른 위치로 옮긴 경우 가상환경은 새 경로에서 다시 만드세요.


- 단위/API: 사각형·빈 마스크·가장자리·분리 영역·구멍의 좌표 계산, 요청 검증, 프레임 일치, 내보내기, 초기화, 삭제 객체의 재등장 방지.
- `smoke_model.py`: 실제 SAM 2.1 분할, 이동하는 도형의 비디오 추적, 두 객체 및 제외 지점.
- `smoke_workflow.py`: 합성 카메라 입력 + 실제 SAM 2.1 + HTTP/WebSocket으로 3개 객체의 선택·추적·보정·삭제·내보내기 전체 흐름. 모형 마스크를 생성해 대신 반환하지 않습니다.
- `logs/model-smoke.json`, `logs/workflow-smoke.json`에 측정 결과가 저장됩니다.
- 프론트엔드 좌표 변환 테스트는 원본 비율·축소·여백·세로 영상·범위 밖 클릭을 검증합니다. 위 Node 테스트는 현재 설치된 Node 24 환경에서 실행할 수 있습니다.

## 구현 방식과 현재 한계

SAM 2.1의 공식 `init_state`, `add_new_points_or_box`, `add_new_mask`, `propagate_in_video` API를 사용합니다.
이전 분석 프레임과 최대 3개의 새 프레임을 짧은 JPEG 구간으로 구성하고, 이전 마스크를 다음 구간의 시작 조건으로 사용합니다.
구간 간 장기 메모리는 초기화됩니다. 모델 내부의 비공개 텐서나 상태를 스트림용으로 임의 확장하지 않습니다.
프레임 JPEG는 처리가 끝나면 삭제됩니다. 카메라 버퍼는 최대 120프레임, 분석 이력은 12개, 객체 경로는 120개로 제한합니다.
지연된 입력은 버퍼 범위에서 최대 3개 프레임을 균등 샘플링하며 최신 프레임을 포함합니다.

카메라 입력과 추론은 별도 스레드입니다. 단일 모델의 GPU 호출은 직렬화하고 WebSocket의 영상 표시 루프와 분리합니다.
RTX 2080 SUPER에서는 BF16을 사용하지 않고 FP32로 추론합니다. CUDA를 사용할 수 없으면 CPU로 실행하지만 속도가 크게 느려질 수 있습니다.
Windows의 CUDA 확장 빌드는 끄고 추가 연결요소/구멍 채우기 후처리를 비활성화했습니다. 마스크 추론과 OpenCV 기반 좌표 계산은 정상 수행합니다.

속도는 입력 크기·객체 수·GPU 부하에 따라 달라집니다. 입력 30FPS가 곧 SAM 추론 30FPS를 뜻하지 않습니다.
빠른 움직임, 긴 가림, 화면 이탈 후 복귀에 대한 추적 품질과 장시간 안정성은 추가 실제 환경 검증이 필요합니다.
8GB GPU에서 다른 AI 프로그램과 동시에 실행하면 메모리 부족이 발생할 수 있습니다. 오류는 화면에 표시하고 추적을 중지합니다.
신뢰도 수치나 소실 후 자동 재식별 성능은 보장하지 않으며 소실 시 보정/재선택할 수 있습니다.

서버는 기본적으로 `127.0.0.1:8000`에만 바인딩하며 외부 클라우드 추론·업로드·배포를 사용하지 않습니다.
API 문서는 http://127.0.0.1:8000/docs 에서 확인할 수 있습니다.

## 연속 재생과 SAM 순차 분석

**재생·추적 방식**에서 선택합니다. 방식 변경은 추적을 일시정지한 상태에서 합니다.

- **연속 재생 · 광학흐름 + SAM 보정**: 동영상을 원본 FPS를 목표로 재생하고, CPU의 특징점 추적과 RANSAC 변환으로 프레임 사이 마스크를 이동합니다. 두 SAM 모델 모두 별도의 백그라운드 스레드에서 보정합니다. 늦게 도착한 SAM 마스크는 측정된 이동 변환으로 현재 프레임에 맞춥니다. 입력 부하에 따라 재생·추적 FPS는 낮아지거나 중간 프레임을 건너뛸 수 있습니다.
- **SAM 순차 분석 · 처리 속도로 재생**: 기존처럼 모든 파일 프레임을 순서대로 SAM으로 처리합니다. 이 모드는 느린 모델에서 화면이 오랫동안 정지해 보일 수 있습니다.

연속 모드의 화면 하단은 `FLOW + SAM`, 내보내기는 `tracking_method: optical-flow+SAM`으로 구분합니다. 모든 프레임이 SAM 추론 결과인 것은 아니며, 보간 마스크·좌표는 추정값입니다. 질감 부족, 가림, 빠른 움직임, 비강체 변형에서 오차가 누적될 수 있습니다. 특징점을 추적하지 못하면 객체를 소실로 표시하며 이전 마스크를 고정해서 성공처럼 표시하지 않습니다. 다시 선택하거나 SAM 순차 분석을 사용하세요.

파일 재생은 객체 선택·보정·일시정지에서 멈추고, 다시 **추적 시작**하면 이어집니다. 일시정지는 백그라운드 추론 완료를 기다리지 않습니다. 재선택·초기화·모델 전환 이전에 시작된 AI 결과는 현재 마스크에 적용하지 않습니다. USB 카메라는 계속 수신하되 추적·분석 결과 갱신을 멈춥니다.

SAM 2.1 연속 추적의 다음 추론은 직전 실제 SAM 출력과 해당 원본 프레임을 기준으로 수행합니다. 표시용으로 보간한 마스크를 SAM 2.1의 다음 입력으로 반복 사용하지 않습니다. 광학흐름 표시는 여전히 추정값이므로 가림이나 비강체 움직임에서 오차가 남을 수 있습니다.

## 실시간 깊이·점군 및 표시 지연 개선 (2026-11-09)

선택 객체 오른쪽의 기본 보기는 **실시간 깊이·점군**입니다. 공식 Depth Anything V2 Small이 영상 전체의 상대 깊이를 추정하고, 같은 프레임의 SAM 마스크 안쪽만 추출해 원본 색상의 3D 점군으로 표시합니다. 움직이는 대상의 현재 보이는 표면을 자동 갱신합니다. 드래그 회전·휠 확대·시점 초기화·점 크기 조절·깊이 갱신 일시정지를 지원합니다. 기존 윤곽 팽창 입체는 기본 UI에서 제거했습니다. 실제 다중 시점 누적 복원은 **3D 스캔**, 두께 없는 배치는 **평면 이미지**를 사용합니다.

깊이 추정 모델은 `setup-depth.ps1`로 설치하며 소스는 `vendor/depth-anything-v2`, 체크포인트는 `models/depth_anything_v2_vits.pth`에 저장합니다. Small 모델과 공식 소스는 Apache-2.0이며 소스 버전은 `a561b849ebae10a6f5ef49e26c83cbbcd36c71bf`로 고정합니다. 출처: https://github.com/DepthAnything/Depth-Anything-V2 . 기존 PyTorch·torchvision 환경을 사용하며 영상은 외부로 전송하지 않습니다.

일반 카메라에서 AI가 추정한 **상대 깊이**이며 카메라 내부 파라미터는 가정값입니다. 실제 거리·치수·정확한 CAD·보이지 않는 뒷면을 제공하지 않습니다. 점군은 객체 중심의 상대 크기로 표시하고 프레임 간 누적하지 않습니다. 가림·반사·마스크 오차·깊이 추정 오차로 누락과 왜곡이 남을 수 있습니다.

깊이 계산은 별도 작업 스레드에서 최신 분석 프레임만 처리합니다. SAM과 GPU 추론 잠금을 공유하고 대기열을 쌓지 않습니다. 열려 있는 깊이 패널의 요청이 중단되면 2초 내 추가 작업이 중단되며 모델은 재사용을 위해 메모리에 남습니다. 최대 5회/초이며 실제 속도는 GPU 부하와 SAM 처리 시간에 따라 낮아집니다. 화면에 원본 프레임 번호·경과 시간·깊이 계산 시간을 표시합니다. SAM 2.1/3.1의 동일한 마스크 인터페이스를 사용하며 SAM 모델 자체는 변경하지 않습니다.

평면 이미지는 기본적으로 선택 순간의 모습입니다. **현재 모습 갱신** 또는 **자동 갱신 · 최대 4FPS**로 별도 갱신합니다.

연속 추적은 새 카메라 프레임 신호에 맞춰 갱신하고, 화면에 필요 없는 원본 JPEG 중복 스트림을 생략합니다. 같은 프레임의 JPEG는 공유하며 브라우저는 최신 결과를 화면 갱신마다 반영합니다. 연속 표시의 윤곽은 직선 구간을 압축하지만 **JSON 내보내기는 전체 픽셀 경계를 유지**합니다. SAM 체크포인트·정밀도는 변경하지 않았습니다. 표시되는 입력→추적 시간은 서버 처리 지연이며 전체 화면 표시 지연과는 다릅니다.
